# Model × Harness Fieldtest

**同一个模型，换个 API 来源、换个编程客户端，到底会不会变笨？**

这个仓库就是从这个疑问开始的。我们没有算力跑一整套排行榜，也不想只看厂商给的分数，于是选几道能看见成品、能实际验收的任务，把不同组合拉起来做同一件事。

| 实验 | 比什么 | 先看什么 |
|---|---|---|
| [DeepSeek V4.1 Flash 1017](experiments/deepseek-v4.1-flash-1017/README.md) | OpenCode Go / 官方 API × OMP / Claude Code | 鹈鹕骑车、真实修 bug、算法题，以及几次翻车 |

我们更关心的是“我平时这样用，拿到的东西怎么样”，不是给模型封一个永久排名。提示词尽量像人说话，允许它自己找文件、改代码、跑程序；最后不听它说完成了就算完成，而是打开网页、运行答案、检查修复。

## 这里会留下什么

不只留下最好看的截图，也留下超时、作废和补跑的来龙去脉。第一轮太容易分不出高下，就补一道更难的；模型读到其他组答案，就承认这次无效；启动脚本搞错了，也会写出来，而不是默默覆盖。

每个实验都放在独立目录：

```text
experiments/<模型及快照>/
  README.md       先看结果，再讲这次怎么测、怎么翻车
  prompts/        真正发给模型的原句
  artifacts/      网页、代码、修复补丁
  results/        脱敏后的记录和截图
  reports/        各阶段详细报告
  evaluation/     独立验收与复现材料
  experiment.json 模型版本、客户端组合、原始项目commit
```

以后换模型或换 harness，就开一个新实验，不把旧结果擦掉。这里的 harness 指管理系统提示、工具、上下文和执行过程的编程环境，比如 OMP 和 Claude Code。

## 也别把它当成什么

不是严格统计研究，不是“这题赢了所以所有任务都更强”，更不是安全审计。每题通常只跑一次，阶段之间也调整过时限和隔离方式。这些差别会说明白；无法比较的费用、被污染的成绩，不硬凑成排行榜。

共享目录保留产物、脱敏摘要和验收工具；**不上传密钥、机器会话数据库、完整原始对话、下载的运行时和依赖**。项目修复用 patch 分享，原始源码通过固定 commit 获取。详细过程中的失误仍会写出来，但私人机器信息不会跟着公开。

Requests / Pytest 片段的上游许可证随实验材料保留。仓库尚未对所有生成作品统一指定开源许可证，使用前请留意这一点。
