# Harness 横向复盘（一）：精简六工具口径下的 Claude Code vs OMP

> **背景说明**：本文基于早期两档实验（[`GLM-5.3（精简工具）`](../experiments/glm-5.3/README.md) 与 [`GLM-5.3-Flash（精简工具）`](../experiments/glm-5.3-flash/README.md)，共 32 场运行，并参考 [`DeepSeek V4.1 Flash 1017`](../experiments/deepseek-v4.1-flash-1017/README.md)）的原始会话流复盘。该阶段启动脚本将两端均限制为六个基础文件/终端工具；放开全套默认内置工具后的后续重测与修正结论见 **[Harness 横向复盘（二）：满血开箱重测后的终评](harness-comparison-full-default.md)**。

直接从 `.local/` 下全部 **32 场原始 `stdout.jsonl` 会话流**里把 API 实报的 token 账单扒出来算了一遍，数据对直觉**证实了一半，也修正了一半**：

1. **“转得更久、收益不明显”完全属实，且 Token 账单差异和耗时高度同步**：32 场合计，Claude Code 墙钟耗时是 OMP 的 **1.62 倍**（`193.0m` vs `119.1m`），Output Tokens 是 **1.59 倍**（`464.5k` vs `292.5k`），按主流缓存/输出计价权重折算，总账单约为 OMP 的 **1.52–1.53 倍**（在 Flash 上更是达到 **1.87–2.00 倍**）。
2. **“Claude 更能兜底、普遍更稳定”并不完全成立——真实情况是两套 Harness 的“翻车模式相反”**：
   - OMP 的翻车是**收敛太快、少做一步边界验证**；
   - Claude 的翻车是**沿着错误假设长线空转、治标不治本**。两边在客观题上其实各有大翻车，并不是 Claude 单向兜底更稳。

## 一、32 场原始日志 Token 与吞吐全量对比

两端连的是同一个智谱官方 `anthropic-messages` 兼容接口，实测 API 生成吞吐几乎完全一致（OMP `43.3 tok/s`，Claude `42.5 tok/s`），且 API 等待占总墙钟的 **94.5%**——也就是说，**Claude 慢出来的每一分钟，几乎都是实打实多吐出来的 Output/Thinking Tokens**。

| 维度（各 8 场 / 合计 16 场） | GLM-5.3 · OMP | GLM-5.3 · Claude | Flash · OMP | Flash · Claude | 16 对合计 · OMP | 16 对合计 · Claude | Claude / OMP |
|---|---:|---:|---:|---:|---:|---:|---:|
| 墙钟总耗时（分钟） | 59.9 | 79.8 | 59.2 | 113.2 | 119.1 | 193.0 | 1.62× |
| API 纯耗时（分钟） | 56.8 | 74.6 | 55.9 | 107.6 | 112.7 | 182.1 | 1.62× |
| 对话总轮数（Turns） | 148 | 147 | 124 | 195 | 272 | 342 | 1.26× |
| 工具调用次数（Tools） | 179 | 165 | 153 | 228 | 332 | 393 | 1.18× |
| 未命中缓存输入（k tok） | 243.4 | 266.7 | 277.1 | 363.5 | 520.5 | 630.2 | 1.21× |
| 缓存读取输入（k tok） | 4,766.5 | 4,639.6 | 3,566.2 | 8,610.2 | 8,332.7 | 13,249.9 | 1.59× |
| 总输入含缓存（k tok） | 5,009.9 | 4,906.4 | 3,843.3 | 8,973.8 | 8,853.2 | 13,880.1 | 1.57× |
| **总输出含思考（k tok）** | **144.8** | **196.3** | **147.7** | **268.2** | **292.5** | **464.5** | **1.59×** |
| 思考文本长度（k chars） | 435.4 | 594.4 | 489.1 | 748.1 | 924.5 | 1,342.5 | 1.45× |
| 折算等价输入（M tok）¹ | 1.78 | 1.98 | 1.58 | 3.16 | 3.36 | 5.14 | **1.53×** |

> ¹ 按通用智谱类权重（未缓存输入 `1×`、缓存读取 `0.2×`、输出 `4×`）折算为等价输入百万 token；若改按 Anthropic 权重（`1 : 0.1 : 5`），三组比值分别为 `1.19×`、`1.87×`、**`1.52×`**，结论不变。

这里面有一个非常关键的分水岭：**强模型 vs Flash 小模型对 Harness 的敏感度完全不同**：
- 在 **`GLM-5.3`** 上，两边轮数几乎一模一样（`148` vs `147` 轮），总输入也几乎打平（`5.01M` vs `4.91M`），折算总花费 Claude 只贵了 **11%–19%**。说明模型推理能力够强时，自己就能把路径走直，Harness 差异被吸收了大半。
- 一旦换到弱一档的 **`GLM-5.3-Flash`**，Claude 轮数膨胀了 **57%**（`195` vs `124` 轮），缓存复读滚雪球到了 **2.41 倍**（`8.61M` vs `3.57M`），单场最夸张的 `Flash R2 D-claude` 一题就跑了 **76 轮、91 次工具、5.45M 输入 + 90.3k 输出（36m47s）**，成本直接翻倍。

## 二、为什么会有“Claude 更能兜底”的体感？拆开看其实是镜像短板

把该阶段所有实验（含 DeepSeek 轮）的失分项放在一起对账，能看清两套 Harness 各自的性格和代价：

1. **OMP 的系统提示词极度强调“克制与最小闭环”，省钱省时，但容易让模型“自信早退”**
   - **首轮基座极薄**：剥离额外组件后，OMP 第 1 轮总输入只有 **4.7k–5.0k tokens**；Claude Code 的系统提示词 + 工具定义首轮就在 **14k–17k tokens** 左右（约 3 倍底噪）。
   - **收敛倾向带来的代价**：OMP 提示词严禁冗余验证和过度设计（*narrowest check, once verified stop and report*）。遇到模型“以为自己想通了”的陷阱题就会少踩一脚刹车：
     - `GLM-5.3 R2 C-omp`：5 轮、62 秒 API 时间写完分治，只测到 $N=2000$ 就收工，漏了 $N=2\times 10^5$ 压测掉到 `39/41`。
     - `Flash R2 D-omp`：27 轮早调 `doCleanups()`，没测普通失败下与 `tearDown` 的先后顺序就自信结案，掉到 `7/11`。
     - **A 题（最影响观感的一项）**：没有量化测试约束且内置浏览器被禁时，OMP 在 Flash 两轮和主实验 R2 都交出了 `8–11 KB`、无 JS 脚本的纯静态 SVG+CSS（最快 `70.5s` 就交卷）；而 Claude 四场全交了 `14.7–19.4 KB` 带完整 JS 动画脚本的页面（哪怕为此烧掉 `19m16s`）。在裸工具开放生成题上，Claude 的“铺张”确实兜住了下限。

2. **但在有明确根因的工程修 Bug 题上，Claude 并没有更稳，甚至贡献了最惨痛的翻车**
   - **B 题该阶段唯一崩盘在 Claude**：跨三个模型共 16 场 B 题里，OMP 全满贯 `7/7`；唯一一次 `3/7` 出在 `Flash R2 B-claude`——它并不是偷懒，而是认认真真跑了 **26 轮、31 次工具调用**，结果一直在修 `method` 表象，完全没碰 `req` 根因。
   - **D 题剔除“偷看上游”后完全平手**：
     - `GLM-5.3` 里剔除 R2 `D-claude` 借 `pip download` 读上游那次，独立推导的 3 场全是 `10/11`；而且在事后双重失败诊断里，唯一顺手写上 `try/finally` 护住现场的反而是 `R1 D-omp`（`R1 D-claude` 连嘴上都说出了“清理异常会被吞”，手头却没修）。
     - `Flash` 里 OMP 拿了一次 `11/11` + 一次 `7/11`（`18/22`），Claude 拿了一次 `10/11` + 一次 `11/11`（`21/22`，但那场 `11/11` 花了近 37 分钟和 5.45M 输入硬磨出来）。

## 三、这套对比结论的重要前提（促成第二阶段满血重测的原因）

这批实验测出来的还不是“完整体 OMP vs 完整体 Claude Code”，而是**“双双卸掉重武器后的裸跑对比”**：
- 启动脚本 `run.py` 为了控制变量，给 OMP 加上了 `--no-lsp --no-skills --no-rules --no-extensions`，只留了 `read,bash,edit,write,grep,glob` 六个基础工具（连 `eval`、`ast_edit`、无头浏览器与 LSP 全关了）；Claude 也关了技能与子代理。
- 因此，该阶段真正测到的变量只有三个：**① 系统提示词的激进/保守程度**、**② 编辑协议差异（OMP 的行号哈希锚点 vs Claude 的全文字符串替换）**、**③ `--thinking high` / `--effort high` 对思考长度的激发程度**。

至于放开全套原生工具之后，哪些短板被立刻填平、哪些预想中的优势根本没触发，见下一篇 **[满血开箱重测后的终评](harness-comparison-full-default.md)**。
